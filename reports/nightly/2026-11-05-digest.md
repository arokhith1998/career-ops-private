### Fixed mid-run: a real PDF-margin defect

The Alcatraz pack-builder found, and I independently verified by rendering
the shipped PDF to an image and measuring pixel margins, that `generate-pdf.mjs`
injects its own `@page` rule *after* a document's own styles. When the
resume/cover-letter HTML does not declare `--page-margin: 0` on `:root`,
that injected rule falls back to a 0.6in default, so the exported PDF gets
roughly 0.9-1.1in margins even when the HTML itself measures edge-to-edge.
Sierra's resume (built earlier in this same run, before the bug was caught)
had exactly this problem. I added the missing declaration and re-rendered it;
page-fit, ATS score and f-pattern are unchanged, and the PDF now matches the
HTML's own 0.3in/0.5in padding. Every pack built after that point
(Alcatraz, Enterpret, Plaid) included the fix from the start and was
measured, not assumed, to confirm it held. `generate-pdf.mjs` itself was not
changed - only the per-pack HTML - so any pack built before tonight should be
assumed to carry the same margin defect until it is re-rendered.
