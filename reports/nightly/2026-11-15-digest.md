### Pipeline bug found (not fixed, flagging for a permanent fix)
`nightly-seen.mjs`'s `record()` treats `DROP:*`/`SKIP:*`/`BUILT` as equally terminal and
sticky, so a verdict never regresses - but it also never **advances** from one terminal state
to another. The Snapmint "Manager, Founder's Office" ledger row (job key
`jobs.weekday.works/manager-founders-office-at-snapmint-4409157639`) was marked
`DROP:below-3.0` by an earlier run even though this role's own queue row scored 3.6 (no_deck,
well above the 3.0 floor - likely a stale/incorrect drop from before a re-score). Running
`--record ... --stage built --verdict BUILT` on it tonight did not change the stored verdict,
because the code's guard is `if (verdict && !isTerminal(prev.verdict))` and `DROP:` already
counts as terminal. The row is removed from the build queue and the tracker correctly shows
the pack as built, so nothing user-facing is wrong, but the ledger itself still reads
`DROP:below-3.0` for a role that was, in fact, built and sent through the full pipeline. Worth
a permanent fix: either let `BUILT` always override a `DROP:`/`SKIP:` (a later, more-advanced
terminal stage should win) or add a one-off reconciliation pass.
