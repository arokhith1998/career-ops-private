### Environment note (read this first)

**Playwright/Chromium is not usable from this cloud sandbox for any live
network navigation.** The session's outbound HTTPS goes through a
TLS-terminating egress proxy; curl, Node's fetch and WebFetch all trust its
CA correctly (via `NODE_EXTRA_CA_CERTS`/`SSL_CERT_FILE`/the system store),
but Chromium uses its own bundled root store and rejects the proxy's
certificate on every navigation (`ERR_CERT_AUTHORITY_INVALID`) — including
the pre-installed "already configured" browser at `/opt/pw-browsers/chromium`,
not just a freshly `playwright install`-ed one. I confirmed this with a
direct test and traced the cause; the fix would be `ignoreHTTPSErrors` on
the browser context, which the auto-mode safety classifier correctly
blocked as a TLS-weakening change, so I left it blocked and did not route
around it. **`check-liveness.mjs` and `browser-extract.mjs` are therefore
dead ends on this box until the environment itself imports the proxy CA
into Chromium's trust store** (or the sandbox is swapped for one where
egress isn't intercepted). Every extraction this run used `WebFetch`
directly per the documented batch-mode fallback; JD files carry no
`**Verification:** unconfirmed (batch mode)` tag individually, but treat
every survivor below as WebFetch-sourced, not browser-confirmed.
