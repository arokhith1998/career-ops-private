Before the numbers below: this session's network egress policy blocked **every** direct WebFetch/Playwright request to job-board domains -- not just LinkedIn/search as `discover-prompt.md` anticipated ("Blocked sources (LinkedIn or search returning nothing) are normal from cloud IPs"). The Node driver's own raw HTTPS calls hit the same wall (128/128 board-harvest fetches HTTP 403, all LinkedIn queries HTTP 403, DuckDuckGo blocked). `github.com` / `raw.githubusercontent.com` and the `WebSearch` tool both work fine -- they're the only channels this environment allows out.

**Practical effect:** every JD below is reconstructed from `WebSearch` snippets (indexed mirrors on freehire.me, Dreamwork, WayUp, h1bgrader, myvisajobs, etc.), never a verbatim fetch of the actual posting. Liveness verification (the mandatory Playwright gate in AGENTS.md) could not run for the same reason -- every report is marked `Verification: unconfirmed (batch mode)`. This is a degraded-but-honest run, not a failed one, but **it will recur on every future cloud discover run until the environment's network policy allowlists job-board domains** (or discovery runs somewhere with fuller egress). Worth a decision from the candidate/operator: reconfigure this environment's network policy, or accept WebSearch-only discovery as the permanent cloud mode.
