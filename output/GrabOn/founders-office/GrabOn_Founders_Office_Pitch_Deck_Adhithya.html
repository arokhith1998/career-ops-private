04
First 90 days

What taking ownership of a GrabOn initiative would look like in practice.

Weeks 1-2
Pick the initiative and the real users
Sit with the team already touching the problem, across GrabOn, GrabCash or GrabShare, to find the one initiative with the clearest unmet need, the same audit that grounded SwipeHire before a line of code existed.
Why first: an MVP built on an assumed problem is the fastest way to ship the wrong thing fast.
Weeks 3-6
Ship the first real version
Build and launch an early version in front of real users, merchants or partners, with success metrics defined up front, the same validate-then-scale sequence that took SwipeHire from PRD to 50+ users.
Why now: a shipped version with one real metric beats a deck with ten projected ones.
Weeks 7-12
Decide, then build the cadence
Use the first metrics to make the scale/change/stop call independently, then set up the review cadence and any AI/agent automation that keeps the initiative running without rebuilding the analysis from scratch each cycle.
Why this fast: a cadence only earns trust once it has already moved one real decision.
